<interfaces>
The final implementation candidate is a full 40-character commit SHA created in the isolated Phase 3 worktree after all production and test changes are complete. Before creating its detached review worktree, the orchestrator requires and creates an absolute `BABYORA_PHASE3_EVIDENCE_ROOT` outside every repository checkout. The candidate record, two review records, and validation bundle live only below that external root. If reviewers request any implementation or test correction, create a new candidate SHA and repeat the validation bundle and both independent reviews.

Review roles are autonomous fresh-context agents: one code/security reviewer and one UI/accessibility reviewer. Neither receives an editable working tree or prior implementation discussion; each receives the exact detached SHA, source artifacts, acceptance matrix, and read-only external validation artifact. `03-08-SUMMARY.md` is written only after verification from the orchestration workspace and may reference external paths/hashes; it is never an input to the candidate SHA or evidence hash.

`scripts/verify-phase3-final.mjs` has two explicit modes. `collect` runs the final command matrix in order, writes combined output to the external validation log, verifies detached/clean HEAD, and writes the candidate JSON. `verify` constructs the candidate/two-review/log paths beneath the same external root and invokes the 03-03 exact-SHA verifier with all dependencies. Both modes read only `process.env.BABYORA_PHASE3_EVIDENCE_ROOT`, resolve/contain the path outside the checkout, and execute child processes through `spawnSync(executable, args, { shell: false })`. npm-family commands always use `process.execPath` as the executable and the validated absolute npm CLI JavaScript entrypoint as argument zero; Git is invoked directly with argument arrays. The PowerShell command contains no evidence path or interpolation.
</interfaces>
