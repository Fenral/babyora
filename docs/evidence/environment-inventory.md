# TASK-008 environment and owner-console inventory

**Status:** COMPLETE — repository configuration is mapped; external console
contents are explicitly unverified unless stated otherwise.

**Decision date:** 2026-08-22

**Scope:** Vercel, MET Norway, RevenueCat, PostHog EU, Sentry, Apple/Codemagic,
and deferred Supabase configuration for the Norwegian validation MVP.

## Safety boundary

- No `.env.local` or external console value was opened, copied, or recorded.
- `.gitignore` excludes `.env*` and deliberately re-includes only
  `.env.example`.
- Every `VITE_*` variable is public because Vite embeds it in the client bundle.
- Secret values belong in owner-controlled Vercel/Codemagic/provider stores or
  a gitignored local file, never in the template or a Vite-prefixed variable.
- A repository reference proves only that configuration is expected; it does
  not prove the value exists in an external console.

Status terms used below:

| Status | Meaning |
|---|---|
| `USED` | A current runtime/build reader exists in the repository. |
| `DECLARED` | Required by the PRD/template but no current reader exists. |
| `CONSOLE-UNVERIFIED` | Local configuration names the console object, but its current contents were not inspected. |
| `DEFERRED` | Must remain empty/inactive until its roadmap capability is authorized. |

| `CODEMAGIC_API_TOKEN` | Local Codemagic-status tool | Secret; invoking shell only. It is not an app runtime variable. |
| `VITE_PLANLEGG_E2E`, `SMOKE_PORT`, `VERIFY_PORT`, screenshot variables | Test/developer tools | Test-only; do not add to production provider consoles. |
| `klemeg_revenuecat` | Codemagic team variable group | Referenced by iOS and Android workflows; group contents remain owner-console evidence. Do not create an app-level group with the same name because it can shadow the team group. |

`APPLE_TEAM_ID` and `APP_BUNDLE_ID` were removed from `.env.example` because no
runtime or build script reads those names. The retained bundle identity lives in
`capacitor.config.ts` and `codemagic.yaml`; Apple signing and store identity are
owner-console configuration, not Vite environment variables.

## Known configuration gaps

1. **Production-domain ambiguity:** the owner-supplied app is
   `snudly.vercel.app`, while Codemagic native builds declare
   `wool-app.vercel.app/api/forecast`; the repo is not locally linked to a
   Vercel project.
2. **MET identity drift:** `.env.example`, the climate-pack contract, and the
   edge proxy do not share one Snudly User-Agent source.
3. **Analytics disabled unless externally configured:** no repository evidence
   proves a PostHog key is injected into Vercel or Codemagic builds.
4. **Sentry is specification-only:** variables alone must not be treated as a
   working monitoring integration.
5. **Console assertions are not clone-verifiable:** Codemagic/RevenueCat/Apple
   names are references; the owner must verify their current external state in
   the later named roadmap tasks.

These gaps are recorded, not fixed, because TASK-008 is an inventory task and
must not change weather, billing, analytics, signing, or release behavior.
